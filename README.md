# AISBench-Prefix-Tools

[📚 在线使用文档](https://ucm-system.github.io/AISBench-Prefix-Tools/)
[🧭 在线设计文档](https://ucm-system.github.io/AISBench-Prefix-Tools/design.html)

Windows 桌面工具，用于远程部署 AISBench 测试环境并自动设计/执行 prefix cache 性能测试，自动提取结果生成 CSV。

## 界面语言

- 支持中文 / English 两种界面语言
- 在左侧边栏底部选择 `语言 / Language`，切换后界面立即重建，无需重启程序
- 界面控件、弹窗提示（如“下一步”校验、部署/清理确认）、远程日志工具界面与状态栏动态消息均随语言切换
- 弹窗按钮（确定/取消/是/否）同样跟随程序语言，不依赖操作系统语言
- 切换语言只改变界面呈现，不重置向导步骤、连接信息与已填写的配置
- 选择会保存到本机用户配置，下次启动自动恢复

## 项目模块

| 文件 | 职责 |
|------|------|
| `main.py` | GUI 主程序（3页界面：SSH连接 + 创建任务 + 任务列表） |
| `ssh_manager.py` | SSH/SFTP 远程连接、命令执行、文件传输 |
| `docker_manager.py` | 执行机镜像列表查询、已有镜像复用、tar 镜像加载、容器管理、代码导入容器、容器内脚本写入、日志下载、残留容器清理 |
| `config_manager.py` | config.py 配置文件生成并直接写入容器内部 |
| `test_designer.py` | 测试用例设计（KV cache 计算、.sh 脚本生成） |
| `log_parser.py` | 测试日志解析、CSV 结果生成 |
| `log_tools.py` | 远程日志工具：选择宿主机/容器日志，筛选 KV cache 并一键填入，查看日志内容 |
| `result_compare.py` | 结果对比分析：两个结果 CSV 按输入规模匹配，差异表格 + 柱状对比图 + 自定义标注 + CSV/PNG 导出 |
| `i18n.py` | 中文 / English 界面文案与语言切换 |
| `task_manager.py` | 任务引擎：多任务并行执行、独立SSH/容器/日志、任务元数据持久化、取消与资源清理 |
| `settings_manager.py` | 用户偏好持久化（界面语言等） |
| `scripts/aisbench_test_designer.py` | 交互式命令行版测试用例设计器（与 GUI 逻辑一致） |

## 快速开始

### 方式一：直接下载 EXE（最简单）

- **最新稳定版**：从 [Releases](https://github.com/ucm-system/AISBench-Prefix-Tools/releases/latest) 页面下载（[直达链接](https://github.com/ucm-system/AISBench-Prefix-Tools/releases/latest/download/AISBench-Prefix-Tools.exe)）
- **手动构建**：在 [Build EXE 工作流](https://github.com/ucm-system/AISBench-Prefix-Tools/actions/workflows/build-main.yml) 页面点击 **Run workflow**，选择分支手动触发；产物在该运行页底部 **Artifacts** 区域下载（保留 90 天，不产生 Release）

双击即可运行，**无需安装 Python 和任何依赖**。

> 首次运行如果弹出“Windows 已保护你的电脑 / 阻止了无法识别的应用启动”，这是 SmartScreen 对未签名新程序的信誉提示：点击 **更多信息** → **仍要运行** 即可；也可右键 EXE → **属性** → 勾选 **解除锁定** 后再运行。原因与处理方式见[常见问题](#常见问题)。

### 方式二：从源码运行

```bash
cd AISBench-Prefix-Tools
pip install -r requirements.txt
python main.py
```

### 方式三：自行打包 EXE（本地使用）

```bash
cd AISBench-Prefix-Tools
pip install -r requirements.txt
build_exe.bat
# 生成 dist/AISBench-Prefix-Tools.exe
```

## 使用流程（3 页界面）

界面共三页：**步骤 1 SSH 连接执行机**、**步骤 2 创建任务**、**步骤 3 任务列表**。原“Docker 部署 / 配置 config.py / 设计测试用例 / 执行测试”四步已合并进“创建任务”单页，按 ①任务资源 → ②服务配置 → ③测试参数与用例 → ④创建任务 四个分区组织；任务创建后自动进入“任务列表”页查看执行状态与全量日志。

### 步骤 1：SSH 连接执行机

| 字段 | 说明 | 示例 |
|------|------|------|
| 执行机 IP | 远程 Linux 服务器地址 | `141.xx.xx.xx` |
| SSH 端口 | 默认 22 | `22` |
| 用户名 | 通常 root | `root` |
| 密码 / 密钥 | 二选一 | 密码（右侧小眼睛可切换明文）或 `.pem` 密钥文件 |

点击 **测试连接** 确认后进入“创建任务”页。连接成功后工具会自动扫描本工具创建的 `aisbench-test-*` 容器，发现上次未清理的容器时会提醒清理。

---

### 步骤 2：创建任务

#### ① 任务资源（镜像 · 代码 · 模型）

| 字段 | 说明 |
|------|------|
| 任务名称 | 可选；留空时自动使用 `服务名_时间`（如 `ds_20261102_153000`） |
| AISBench 镜像来源 | 点击 **查看已有镜像**，直接选择执行机上已存在的 Docker 镜像；列表上方提供 **筛选** 输入框，可按关键字（不区分大小写）实时过滤长镜像名；未发现可用镜像时自动切换为 **上传本地镜像tar包**，并保留镜像下载链接 |
| 测试代码来源 | **程序内置**（默认，随 EXE 打包，部署时自动上传）或 **本地 zip 包**（zip 模式附代码下载链接按钮） |
| 模型路径 | 点击 **浏览远程目录** 在远程主机目录树中定位模型权重目录 |
| 临时部署目录 | 默认 `/tmp/AISBench_Prefix_Tools`，可点击 **浏览远程目录** 选择其他基目录；每个任务会在其下创建独立子目录，仅部署期间暂存镜像tar/代码，导入容器后自动删除，不保留在宿主机 |
| 残留容器清理 | 点击“清理残留容器”可查看并删除上次退出时未清理的 `aisbench-test-*` 容器 |

#### ② 服务配置

| 字段 | 说明 |
|------|------|
| 模型名称 | 默认 `ds`（对应 vLLM `--served-model-name`） |
| 服务 IP / 端口 | 留空自动使用执行机 IP / `8000` |
| API Key（可选） | 需要鉴权的 vLLM 服务填写 |
| POD_INFO | 多 DP 场景填写，格式 `ip:port,ip:port`；单 DP 留空 |

> 服务配置独立分区、两行多列紧凑排布，默认全部自动生成，仅在特殊场景需要修改。

#### ③ 测试参数与用例设计

填写 KV cache 信息（从 vLLM 启动日志获取）。界面内置查询命令，点击 **复制** 后可直接在服务器上执行：

```bash
cat vllm_serve.log | grep -e 'KV cache size' -e 'Maximum concurrency'
```

> 命令使用通用的 `KV cache size` 关键词（而非 `GPU KV cache size`），兼容 GPU / NPU 等不同生态的日志输出。

也可以点击 **从日志自动获取 / 查看日志** 打开远程日志工具：

- **服务器**：当前执行机，或临时连接其他服务器（关闭对话框自动断开）
- **日志来源**：宿主机文件 / 指定容器内文件（自动列出运行中容器）/ 容器 stdout（docker logs）
- **筛选 KV cache**：对选定日志执行 grep，直接显示匹配行；解析出“单个DP组KV cache”与“模型最大上下文”后可**一键填入**，同时界面查询命令更新为实际执行命令
- **查看日志**：独立窗口查看日志内容（文件取尾部 2MB，docker logs 取尾部 5000 行，支持横向滚动与一键复制）

| 字段 | 说明 | 示例 |
|------|------|------|
| 单个DP组KV cache | 单 DP 组的 cache 容量 | `198469` |
| DP组数 | data-parallel-size | `4` |
| 最大请求长度 | 单条请求最大 token 数 | `32768` |
| 前缀命中率 | repeat_rate，0~1 | `0.9` |
| 请求发送速率 | 0 = Burst 模式；>0 为固定发送速率 (req/s)，支持小数如 `0.3` | `0` |

勾选测试的 **输入长度**（预设 8K ~ 2M，超出模型最大上下文的选项生成时会明确提示跳过）和 **输出长度**，点击 **生成测试用例**。

工具自动计算（下方“计算明细”面板展示每个用例的代入过程）：
- **最小请求数** = `floor(total_kv_cache / input_len / repeat_rate) + 1`
  （低于该值时请求前缀总量不会超出 HBM KV cache 容量，不会命中 HBM 之外的 KV cache 缓存介质）
- **推荐请求数** = 最小请求数 × 2
- **并发数** = `floor(total_kv_cache / (input_len + output_len))`（KV cache 使用率 ≈ 100%）

生成的用例表格包含 **请求数(推荐) / 前缀数量(prefix_num) / 请求数(最小) / 并发数 / KV使用率** 列（表格与计算明细区域可拖拽分隔条调整占比），支持：
- **双击单元格** 编辑 Input / Output / 请求数 / 前缀数量 / 并发数
- **前缀数量** 对应 AISBench 命令的 `--prefix_num` 参数；默认与该用例请求数一致，修改请求数时会自动同步，用户单独修改后则保持自定义值
- 请求数允许低于最小值，低于时仅弹窗提醒（提示不会命中 HBM 之外的缓存介质），不强制拦截
- **添加用例 / 复制用例 / 删除用例** 按钮管理用例列表

#### ④ 创建任务

完成配置后，点击 **🚀 创建任务**：工具先弹出 **全量信息确认对话框**，汇总任务资源、服务配置、测试参数与执行流程，确认后才会开始执行。也可以随时点击 **预览任务信息**（未创建任务同样可用）查看当前表单汇总。

确认执行后：

```
部署容器（复用已有镜像 / 上传加载 tar）
        ↓ 检查 Docker → 准备镜像 → 暂存代码 → docker run 创建容器(仅挂载模型) → docker cp 导入代码 → 清理宿主机暂存目录
自动写入 config.py（原“配置文件”步骤，合并进任务流程）
        ↓ 服务参数默认自动生成（ds / 执行机IP / 8000）→ 写入容器 → 回读验证一致
执行测试并生成 CSV
        ↓ 预检查 MODEL_PATH → 生成 .sh → 容器内执行 → 下载日志 → 解析 CSV
```

部署细节：

```
[1/5] 检查远程机 Docker 环境
[2/5] 准备 AISBench 镜像
        ↓ 已有镜像模式: 校验执行机镜像存在后直接复用
        ↓ 上传模式: 预读 manifest.json, 已存在则跳过, 否则 SFTP 上传并 docker load -i
[3/5] 暂存测试代码（程序内置 或 本地 zip 包）
[4/5] 创建并启动容器(仅挂载模型路径):
        docker run -itd \
          --name aisbench-test-<任务名>-<时间>  \  ← 自动生成容器名(基于任务名称)
          --shm-size=1g --net=host \
          --label org.aisbench-prefix-tools.managed=true \
          -v <模型路径>:<模型路径> \
          <镜像名> python3
[5/5] docker cp 导入测试代码到容器内 /benchmark/ais_bench/aisbench_auto_tools_prefix-main
        → 删除宿主机临时目录（部署成功后不再保留）
```

config.py 自动生成并写入容器（无需手工填写与保存）：MODEL_NAME / HOST_IP / HOST_PORT 等服务参数来自“服务配置”分区（默认自动生成，可修改），MODEL_PATH 来自任务资源，DATASET_PATH 自动指向容器内代码工作区；写入后自动回读验证，关键配置不一致时会中止执行并在日志中说明。POD_INFO 在多 DP 场景于服务配置中填写（格式 `ip:port,ip:port`）。

测试执行阶段：

```
[0/4] 预检查: 验证容器内 MODEL_PATH
        ↓ 路径存在且含 config.json，否则快速失败并提示原因
[1/4] 生成 .sh 测试脚本
        ↓ test_designer 生成包含所有测试用例的 bash 脚本
[2/4] 写入测试脚本到容器内部并执行
        ↓ base64 编码写入 run_tests.sh → 容器内 bash run_tests.sh
[3/4] 下载测试日志到本地
        ↓ docker cp 容器日志 → SFTP 下载到 Windows 本地目录
[4/4] 解析日志生成 CSV
        ↓ log_parser 解析第二次测试结果，输出 CSV 到本地
```

生成的测试命令示例：

```bash
python3 aisbench_test.py \
  --prefix_test \
  --input_len 16384 \
  --output_len 512 \
  --data_num 108 \
  --prefix_num 108 \
  --concurrency 46 \
  --dataset_type prefix_cache \
  --repeat_rate 90% \
  --dp 4 \
  --seed 385712
```

其中 `--seed` 每次执行随机生成（数据集可复现、不同轮次不同）；请求发送速率 > 0 时还会追加 `--request_rate <速率>`。
`--prefix_num` 取自用例表格中的“前缀数量”列；未单独修改时等于 `--data_num`。

**本地结果保存目录**：任务页可选择 Windows 本地目录（默认 `C:\Users\<用户名>\aisbench_results`）。

测试完成后自动产出：
- **CSV 文件**：`results_test_logs_<时间戳>.csv`（包含 TTFT/TPOT/E2EL、吞吐量、命中率等指标）
- **日志文件**：`test_logs_<时间戳>/test_<序号>_<input>_<output>.log`（每个用例独立文件，同长度多测试也能分别解析出结果）

任务的执行进度实时输出到“任务列表”页的 **执行日志** 区域（自动跟随最新输出，向上翻阅查看历史时不强制滚动），日志支持全屏显示，同时写入本地日志文件（工具数据目录 `logs/` 下，每个任务一个文件）。完成后在 **结果摘要表格** 中直接展示关键指标（Input / Output / 请求数 / 最大并发 / 并发 / 输入吞吐 / 输出吞吐 / TTFT / TPOT / QPS / HBM 命中率 / 外部缓存命中率，并标注 CSV 与日志路径），同时日志区也打印文本摘要表：

```
结果摘要:
-----------------------------------------------------------------------------------------------------------------------------

   16384      512    108       46       46     4523.1      312.5       45.2       12.3      8.5       92.3       91.8
   16384     1024    108       45       45     4410.8      290.1       48.1       11.8      7.2       92.5       91.6
   32768      512     54       23       23     3895.4      201.7       52.6       13.1      6.1       94.8       95.1
```

### 步骤 3：任务列表

任务创建后自动跳转到“任务列表”页；该页签始终可访问，与“创建任务”解耦。

| 区域 | 说明 |
|------|------|
| 任务表格 | 每行一个任务：任务名称、状态（排队中/部署中/配置中/执行中/已完成/失败/已取消/已中断）、创建/结束时间、镜像、模型路径、容器、结果文件 |
| 执行日志 | 选中任务后显示其全量日志（终端进度行自动折叠）；**全屏显示** 按钮放大为独立窗口 |
| 结果摘要 | 任务完成后展示指标表格，可打开本地结果目录 |
| 操作栏 | 刷新 / 复制新建 / 取消任务 / 清理资源 / 删除数据 |

任务管理能力：

- **多任务并行执行**：每个任务使用独立 SSH 连接、独立容器与独立临时目录，互不干扰；任务元数据持久化（`tasks.json`），重启程序后自动恢复任务列表（执行中的任务标记为“已中断”）
- **复制新建**：把已有任务的全部配置回填到“创建任务”表单，微调后即可创建新任务
- **取消任务**：终止运行中的任务（执行阶段会停止容器以中断测试；已下载的本地结果不受影响）
- **清理资源**：删除任务对应的容器与远程暂存目录（需已连接执行机）；清理后如需再次执行，重新创建任务即可
- **删除数据**：删除任务记录，可选择同时删除本地日志与结果文件以释放磁盘空间
- 每个任务的执行日志同时写入本地文件：工具数据目录 `logs/<任务ID>.log`

> 任务名称可在创建时指定；留空自动使用 `服务名_时间`。

### 结果对比分析

结果对比分析为**独立工具，无需连接执行服务器**，两种入口随时可用：

- 左侧边栏 **📊 结果对比分析** 按钮（应用启动后即可使用）
- “任务列表”页 **结果摘要** 标签旁的按钮（测试完成后就近使用）

选择两个工具生成的结果 CSV 文件（`results_*.csv`）：

- **格式校验**：表头字段必须与工具生成的 CSV 格式完全一致，缺少/多余字段会明确提示
- **自定义标注**：选择 CSV 后自动用文件名填充 A/B 标注，可直接改成“基线 v1”“优化后 v2”等业务名称；图例与导出文件名使用标注，重新选择文件不会覆盖已手工修改的标注
- **用例匹配**：先按（输入长度 + 输出长度）精确匹配，剩余用例回退按输入长度匹配（标注匹配方式）；匹配列表同时展示两侧请求数与 Max_CC；勾选参与对比的用例
- **指标选择**：21 个指标按 TTFT / TPOT / E2E 延迟 / 吞吐 / 命中率分组勾选，默认选中常用 6 项
- **差异表格**：Req A/B、Max_CC A/B 两列 + 每个指标 4 列（A 值 / B 值 / Δ = B−A / Δ%）；窗口可最大化/全屏，表格支持鼠标拖拽、滚轮纵向滚动和 Shift+滚轮横向滚动
- **柱状对比图**：每个指标自动绘制分组柱状图（A 蓝 / B 橙，自定义标注为图例），横坐标展示 输入/输出/请求数/Max_CC（两侧不同以 A↔B 标注），随窗口宽度自适应
- **导出对比 CSV**：将当前对比表格保存为 CSV 文件，默认文件名包含 A/B 标注
- **导出对比图**：把当前勾选指标的柱状图逐张导出为 PNG（1280×640），文件名形如 `compare_基线v1_vs_优化后v2_TTFT平均.png`，可直接用于报告和归档

### 环境清理与退出

- 在“任务列表”页选中任务后点击 **清理资源**，删除该任务的容器与远程暂存目录；清理提示会显示容器内测试任务状态，并说明清理后再次执行需重新创建任务（重新部署容器）
- 退出程序时（窗口 **×**），若有任务仍在执行会先确认；存在未清理容器资源的任务时弹出清理提醒：清理后退出 / 保留环境直接退出 / 取消
- 若上次退出时未清理容器，本次连接成功后会自动扫描 `aisbench-test-*` 容器并提醒；也可在“创建任务”页点击 **清理残留容器** 勾选删除（支持同时清理旧版遗留的临时目录），列表会显示每个容器的测试任务状态
- 残留容器清理只识别本工具创建的容器（`aisbench-test-` 前缀或管理 label），不会影响执行机上的其他容器

#### 容器内测试任务状态标记

本工具创建的容器会在容器内工作目录写入 `.aisbench_test_state` 标记文件，记录测试任务的执行状态；清理容器（自动提醒 / 清理环境 / 清理残留容器）时会展示该状态：

| 状态 | 对应阶段 / 场景 |
|------|----------------|
| 初始化 | 部署完成（测试代码已导入容器），测试尚未开始 |
| 执行中 | 测试脚本正在容器内执行 |
| 执行完成 | 测试脚本成功执行完毕 |
| 异常终止 | 测试脚本失败或中断退出；若上次会话退出时测试仍在执行（容器已停止但状态停留在“执行中”），清理列表中会显示为“异常终止(执行中断)” |
| 未标记 | 旧版本创建的容器，未写入状态标记 |

> 注意：清理会停止并删除容器，config.py、测试脚本和日志都保存在容器内部。清理后如需再次执行测试用例，需要重新创建任务（重新部署容器）。

## 常见问题

**Q: 执行机上已有镜像，还需要上传 tar 包吗？**
A: 不需要。在“创建任务”页点击 **查看已有镜像**，从列表选择镜像后直接部署；工具会校验该镜像仍存在并跳过上传与加载。未发现可用镜像时才需要切换到上传模式。

**Q: 执行机镜像太多，找不到目标镜像怎么办？**
A: 查看已有镜像后，在下拉框左侧的 **筛选** 输入框输入关键字（如 `aisbench`、镜像 tag、仓库名片段），列表会按子串实时过滤且不区分大小写，并显示“筛选: N/M 个镜像”；清空关键字即可恢复完整列表。若当前关键字无匹配，会提示调整关键字而不是自动切换到上传模式。

**Q: 上传镜像后无法自动识别镜像名？**
A: 工具优先在本地直接读取 tar 包内 `manifest.json` 获取镜像名（无需上传）；读取失败时再由 `docker load` 输出的 `Loaded image:` 行识别。可在任务页部署日志中查看解析结果。

**Q: 如何切换中文 / English 界面？**
A: 在左侧边栏底部选择 `语言 / Language`；界面会立即重建，选择会保存到本机用户配置，下次启动自动恢复。

**Q: 模型路径浏览看不到文件？**
A: 远程目录浏览器默认从 `/` 开始，双击 `[DIR]` 进入子目录。部分目录可能因权限问题无法列出。

**Q: POD_INFO 怎么填？**
A: 单 DP 场景留空即可（自动使用 HOST_IP:HOST_PORT）。多 DP 场景填写每个节点的地址，逗号分隔，如 `141.1.1.11:8000,141.1.1.12:8000`。

**Q: 如何重新部署？**
A: 再次点击 **创建任务**（或在“任务列表”页对旧任务使用 **复制新建**）即可创建新容器；旧任务容器可通过 **清理资源** 或 **清理残留容器** 删除。也可手动 `docker rm -f <容器名>` 后重试。

**Q: 上次退出没有清理，怎么删除遗留容器？**
A: 重新连接执行机后，工具会自动扫描 `aisbench-test-*` 容器并提醒；也可以在“创建任务”页点击 **清理残留容器**，在列表中勾选要删除的容器（可同时清理旧版本遗留的 `/tmp/AISBench_Prefix_Tools` 临时目录）。列表会显示容器内测试任务状态（初始化/执行中/执行完成/异常终止），便于判断上次测试是否中断。清理只针对本工具创建的容器。

**Q: 清理环境后想再次执行测试怎么办？**
A: 清理会停止并删除容器，config.py、测试脚本和日志都保存在容器内部。重新点击 **创建任务** 即可重新部署容器、自动写入配置并执行测试（用例设计已保留，无需重新填写）。

**Q: 远程的 /tmp/AISBench_Prefix_Tools 目录为什么部署后不见了？**
A: 该目录现在只是部署过程的临时暂存区，用于上传镜像 tar/测试代码。代码通过 `docker cp` 导入容器后，工具会自动删除该目录；后续 config.py、测试脚本和日志都保存在容器内部，不再依赖宿主机目录。

**Q: SSH 连接超时？**
A: 检查防火墙、安全组是否放行 SSH 端口；确认 IP 和端口正确；如使用密钥，确保密钥格式为 RSA 或 Ed25519。

**Q: 双击 EXE 提示“Windows 已保护你的电脑 / 阻止了无法识别的应用启动”？**
A: 这是 Microsoft Defender SmartScreen 的**信誉机制提示**，不是病毒查杀结果。原因有两个：目前发布的 EXE 未做代码签名；文件通过网络下载时 Windows 会附加“网络来源”标记（Mark of the Web），SmartScreen 对没有信誉记录的新程序默认拦截。任选一种方式运行：

- 在弹窗中点击 **更多信息** → **仍要运行**；
- 右键 EXE → **属性** → 勾选底部的 **解除锁定** → 确定后再双击；
- PowerShell 执行 `Unblock-File .\AISBench-Prefix-Tools.exe`；
- 从源码运行或本地执行 `build_exe.bat` 打包（本地生成的文件没有网络来源标记）。

要从根本上消除该提示，需要对发布的 EXE 做代码签名：EV 证书可立即获得 SmartScreen 信誉，OV 证书会随分发逐步建立信誉，Azure Trusted Signing 也可在 CI 中集成。EXE 由 GitHub Actions 从本仓库源码构建，也可自行从源码构建以校验行为。
