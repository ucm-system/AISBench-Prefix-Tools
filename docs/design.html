1. 文档目的

本文档用于向外部架构师、性能工程师和产品评审人员说明 AISBench-Prefix-Tools 的设计原理与实现边界，帮助评审者判断方案是否满足目标场景，以及后续演进的合理性。

使用场景 使用方式 总体架构 模块设计 执行流程 核心算法 日志工具设计 结果对比设计 数据契约 安全与部署 扩展与评审 术语表
评审关注点 本文档重点回答三个问题：为什么需要这个工具；用户如何完成一次完整测试；系统如何把远程部署、用例生成、日志解析和结果对比组织成可维护的产品。

2. 使用场景

2.1 目标用户

推理工程师

需要验证 vLLM prefix cache 在不同输入长度、输出长度、并发和请求数下的收益。

性能测试人员

需要在远程 GPU 服务器上重复执行标准化压测，并得到可对比的结构化结果。

交付与验收人员

需要用同一套流程比较基线与优化版本，输出可留档的 CSV 和图表。

平台研发人员

需要定位 KV cache、外部缓存命中率和吞吐指标之间的关系。

2.2 典型场景

  • 在 Windows 本机操作一台或多台远程 Linux GPU 服务器，部署 AISBench 测试环境。
  • 从 vLLM 启动日志中提取 KV cache 容量和最大上下文，自动推导测试用例。
  • 执行多组 prefix cache 压测，自动下载日志并生成统一格式 CSV。
  • 离线选择两个结果 CSV，比较相同输入规模下的性能差异，并自动绘制柱状图。
  • 远程查看宿主机或容器内日志，避免手工复制 grep 命令和逐台排查。

2.3 设计边界

工具聚焦 prefix cache 性能测试与结果分析，不承担模型训练、服务运维或通用压测平台职责。

3. 使用方式

产品提供 Windows 桌面向导和两个独立分析入口。用户不需要在本机安装 Python 或容器环境，只需要具备远程服务器访问权限和必要的模型、镜像资源。

3.1 输入

  • 远程执行机 SSH 信息：IP、端口、用户名、密码或密钥。
  • 执行机已有的 AISBench Docker 镜像或可上传的镜像 tar 包，以及程序内置测试代码。
  • 模型权重路径、模型名称、vLLM 服务地址和鉴权信息。
  • KV cache 参数：单个 DP 组容量、DP 组数、最大请求长度、前缀命中率、请求发送速率。
  • 结果对比模式下的两个 CSV 文件。

3.2 输出

  • 远程 Docker 容器和测试脚本。
  • 每个用例独立日志文件。
  • 结构化结果 CSV。
  • 结果摘要表格、差异表格和柱状对比图。
  • 远程日志筛选结果和日志查看窗口。

3.3 用户主流程

连接服务器→ 选择镜像/模型并部署容器→ 生成配置→ 设计用例→ 执行测试→ 生成 CSV→ 对比分析
交互原则 每一步只暴露当前必须确认的信息；前置步骤的结果自动带入后续步骤，减少重复输入和手工传递错误。

4. 总体架构

系统采用“本地 GUI + 远程执行 + 本地分析”的分层架构。GUI 负责交互与编排，远程层负责服务器与容器操作，数据层负责脚本生成、日志解析和结果分析。

交互层→ 流程编排层→ 远程执行层→ 数据生成层→ 解析分析层

4.1 架构分层

层次职责关键内容
交互层接收用户输入，展示流程与结果五步向导、日志工具、结果对比窗口
流程编排层控制步骤顺序与状态流转步骤校验、任务调度、错误提示
远程执行层管理远程主机与容器SSH/SFTP、Docker 部署、脚本上传与执行
数据生成层生成配置和测试脚本config.py、run_tests.sh、用例参数计算
解析分析层解析日志并对比结果CSV 生成、指标计算、图表绘制

4.2 关键设计决策

  • 桌面端而非 Web 端：测试人员通常在 Windows 本机操作，桌面端降低部署门槛，便于直接访问本地文件和远程 SSH。
  • 远程执行而非本机执行：GPU 和模型在 Linux 服务器上，本机只负责编排，避免跨平台容器和驱动问题。
  • 容器化隔离：测试环境运行在 Docker 容器中，减少依赖冲突，便于重复部署与清理。
  • 结构化 CSV 作为数据契约：所有测试结果统一输出 CSV，保证后续分析、归档和对比稳定。
  • 分析工具独立：结果对比不依赖执行服务器，可以在任意本机离线使用。

6. 执行流程设计

6.1 五步向导

  1. SSH 连接：校验远程主机可达性和认证方式。
  2. Docker 部署与模型配置：查看并选择执行机已有镜像；无可用镜像时上传 tar 包，同时配置代码、模型路径和 vLLM 服务，并一键部署容器。
  3. 配置生成：写入 config.py，并支持回读校验。
  4. 用例设计：根据 KV cache 参数自动生成测试用例。
  5. 执行测试：上传脚本、执行、下载日志并生成 CSV。

6.2 状态与容错

  • 每一步完成后再进入下一步，避免在连接失败时继续部署。
  • 优先复用执行机已有镜像；仅在上传模式或镜像缺失时执行 SFTP 上传与 docker load。
  • 同名容器自动清理后重建，保证测试环境一致。
  • 执行完成后自动下载日志，本地结果不受远程清理影响。

7. 核心算法设计

用例自动设计的核心目标是：在不超出 KV cache 容量的前提下，生成能稳定触发 prefix cache 行为的请求数和并发数。

7.1 参数定义

参数含义来源
total_kv_cache总 KV cache 容量单个 DP 组 KV cache × DP 组数
input_len输入 token 长度用户选择或手动编辑
output_len输出 token 长度用户选择或手动编辑
repeat_rate前缀命中率用户配置，范围 0~1

7.2 计算公式

最小请求数 = floor(total_kv_cache / input_len / repeat_rate) + 1
推荐请求数 = 最小请求数 × 2
并发数 = floor(total_kv_cache / (input_len + output_len))

7.3 设计意图

  • 最小请求数：确保请求前缀总量足以超过 HBM KV cache 容量，从而观察到外部缓存介质的命中行为。
  • 推荐请求数：预留两倍余量，降低随机波动对结论的影响。
  • 并发数：让 KV cache 使用率接近 100%，同时避免单纯因为资源不足导致异常。
  • 最大请求长度：用于过滤超出模型上下文的非法组合。
边界情况 若用户手动将请求数降到最小值以下，工具只提示风险，不强制拦截，以便进行对比实验。

8. 远程日志工具设计

日志工具解决两个问题：一是避免用户手敲 grep 命令，二是让用户可以在不登录服务器的情况下查看和筛选远程日志。

8.1 支持的日志来源

来源获取方式适用场景
宿主机文件SSH/SFTP 读取远程文件直接查看服务器上的 vLLM 日志
容器内文件列出运行中容器后进入容器读取日志挂载在容器内部
容器 stdout读取 docker logs日志未落盘，仅输出到标准输出

8.2 关键行为

  • 自动生成实际执行的 grep 命令，用户可复制或直接执行。
  • 解析“GPU KV cache size”和“Maximum concurrency”等关键行。
  • 支持一键填入测试参数，减少手工抄写错误。
  • 文件日志取尾部 2MB，容器 stdout 取尾部 5000 行，避免一次性拉取过大日志。

9. 结果对比分析设计

结果对比分析是独立入口，不依赖执行服务器。它以两个工具生成的 CSV 为输入，输出差异表格和柱状图。

9.1 匹配规则

  1. 优先按输入长度和输出长度精确匹配。
  2. 未匹配的剩余用例回退为仅按输入长度匹配，并标注匹配方式。
  3. 匹配列表同时展示两侧请求数和 Max_CC，避免误把测试条件差异当成性能差异。

9.2 指标体系

支持 TTFT、TPOT、E2E 延迟、吞吐、命中率等 21 个指标，按类别分组展示。默认选中常用指标，用户可按需勾选。

9.3 输出设计

输出内容目的
差异表格A 值、B 值、Δ、Δ%量化对比结果
柱状图按指标分组，横轴展示输入、输出、请求数、Max_CC直观观察趋势
导出 CSV保存当前对比表归档与二次分析
设计原则 分析层只做纯本地计算，不访问执行服务器，保证离线可用。

11. 安全与部署设计

11.1 安全原则

  • SSH 密码或密钥仅用于建立连接，不随测试结果上传。
  • 远程操作限定在独立工作目录和专用容器中，避免影响宿主机环境。
  • 容器默认使用主机网络和必要的模型目录挂载，不额外开放端口。
  • 日志和 CSV 保存在用户指定的本地目录，便于审计和备份。
  • 远程清理只删除本工具创建的容器和工作目录，不触碰其他数据。

11.2 部署方式

方式适用人群特点
下载 EXE测试与交付人员免安装，双击即用
源码运行研发人员便于调试与二次开发
本地打包需要定制版本的用户生成独立 EXE

11.3 运行环境

  • 客户端：Windows 10/11。
  • 执行机：Linux，具备 Docker 和 SSH 访问权限。
  • 推理服务：可访问的 vLLM 服务地址。
  • 资源：执行机已有 AISBench 镜像或可上传的镜像 tar 包，以及模型权重。

12. 扩展性与评审要点

12.1 可扩展方向

多服务器编排

将单执行机扩展为集群任务调度，支持多节点并行测试。

更多推理引擎

抽象日志解析与参数适配层，支持非 vLLM 引擎。

结果趋势分析

在两组对比之外增加多轮趋势、回归检测和阈值告警。

报告导出

把 CSV、图表和结论自动生成 HTML 或 PDF 报告。

12.2 评审建议关注点

  • 用例生成算法是否满足 prefix cache 测试目标。
  • CSV 字段是否能覆盖后续性能归因需求。
  • 远程执行层的错误恢复和幂等策略是否足够。
  • 结果对比的匹配规则是否会产生误导性结论。
  • 远程日志工具的权限边界与安全控制是否合理。
已知限制 当前版本主要面向单台执行机和 vLLM 场景；多服务器协同和自动报告生成仍在演进范围内。

13. 术语表

术语解释
Prefix cache针对重复请求前缀的缓存机制，可降低重复计算并提升响应速度。
KV cache推理过程中保存 Key/Value 的缓存空间，容量会影响并发和吞吐。
DPData Parallel，数据并行组数。
TTFTTime To First Token，首 token 延迟。
TPOTTime Per Output Token，平均每个输出 token 的耗时。
Max_CC最大并发数，用于标识测试并发条件。
HBM 命中率命中显存 KV cache 的比例。
外部缓存命中率命中 HBM 之外缓存介质的比例。
